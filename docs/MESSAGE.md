# Page 5 Message

依 LineFlow `docs/ANDROID_WEBSOCKET_GUIDE.md` 實作（2026-09-27 透過 SSH 讀取）。

## 使用

1. 安裝 debug APK，開啟第 5 頁 **Message → 連線設定**。
2. 預填端點為 `wss://your-server.example.com/ws/lineflow`，實例為 `instance1`。填入 Server 的 Access Token，再按「儲存並開始」。Token 不隨 APK 提供。
3. 允許通知；在「通知音效／彈出設定」確認搶單提醒可發出聲音、震動及彈出。
4. 可切換其他頁面或讓 App 進入背景。常駐通知表示接收服務運作中；頁面及常駐通知會顯示斷線／重連狀態。按「停止」會關閉接收，且下次開啟 App 不自動接收。

預設關鍵字為 `即時可等`、`報分`、`跳表`、`自費`、`+300`、`+400`。Page 5 的「關鍵字設定」開啟彈窗，每行一個，最多 50 個、每個最多 40 字；可恢復預設或清空以停用提醒。儲存後立即重算清單高亮並套用背景接收，不補發歷史通知。使用本機規則即時分析，不需 AI 網路呼叫。正規化全形與空白，`＋３００`、`+ 400` 可命中；`+3000` 不誤判成 `+300`。只分析訊息本文，顯示聊天室、發話者、Server 時間與 LINE 顯示時間。

命中訊息卡片高亮；尚未讀取的命中訊息讓第 5 頁頁籤高亮並顯示數量。進入頁面不自動清除提醒，按個別「標為已讀」或「全部已讀」清除。新訊息仍會繼續計數。清單顯示最新 500 則，可篩選關鍵字訊息或複製原文；資料庫保留較舊訊息。

## 收訊與通知語意

- `new_message` 儲存成功後，命中關鍵字即發高重要性通知；通知可開啟第 5 頁。
- 每個 Server／實例的首次同步不通知歷史訊息。後續重連只對最近 120 秒補收的命中訊息通知，避免舊單提醒。
- SQLite 唯一鍵為來源（Server＋instance_id）與 seq_id；訊息與游標在同一交易提交。重複推送不重複通知。Token 更新沿用同一來源的游標。
- 同步中收到即時訊息，先保存訊息但不把同步游標跳到新序號；每滿 500 筆持續分頁，最後才合併即時進度，避免跳過中間訊息。
- 每 25 秒 JSON ping；約 60 秒沒有回應或同步沒有完成會重連（以心跳檢查週期偵測）。指數退避 1/2/4/8/16/30 秒加抖動；重新建立連線必定先 auth，收到 auth_ok 後才 sync。
- close 1008、1003 或 HTTP 401/403/404 會顯示設定錯誤並停止自動接收，修正後手動開始。
- 使用 `remoteMessaging` 前景服務接收從 LINE 實例轉來的文字訊息。Android 強制停止 App、裝置省電限制、無網路或關閉通知時，不能保證即時彈出；下次接收會補收。回覆與上下車回報均由使用者操作觸發，沒有自動搶單。
- 程序異常終止後，已持久化但尚未送出的系統通知不保證重送；未讀高亮仍會保留。

## 安全與部署

Token 使用 Android Keystore 金鑰進行 AES-GCM 加密，設定與 SQLite 放在 noBackupFilesDir，不進系統備份或 Firebase。Token 不放入 URL，也不列印認證封包及 Server 的 auth_fail 原因；設定物件的 toString 不包含 Token。App debug 與 release 均使用 WSS，維持系統 TLS 憑證與主機名稱驗證；明文僅能由單元測試明確開啟且只限 loopback。

連線後第一則 JSON 是 `auth`（token、instance_id）。等到 `auth_ok` 才同步、心跳或允許發送；提供 instance_id 時會核對。`auth_fail` 停止接收並提示重新設定，15 秒沒有握手結果則退避重連、重新 auth。已儲存的舊 IP 端點自動升級至新 WSS 網域，保留加密 Token、instance_id、訊息、同步游標及傳送紀錄。

Android 前景服務類型參考：https://developer.android.com/develop/background-work/services/fgs/service-types#remote-messaging

## 插單可行性評估及回覆

高亮訊息的「計算時間」改為「評估可行性」。彈窗把訊息整理成插單起點、終點、接客日期、時間／時間區間或即時可等；欄位均可修正。AI 不猜車程，缺少接客時間時必須補填或自行選即時可等。

依目前時間及 Page 2 資料判斷執行中的行程：尚未完成，且目前在「接客時間至接客時間＋車程＋上下車各 5 分鐘」內，就從該趟下車地點、預計下車完畢時間出發；否則使用現在位置。既有行程車程優先使用手填分鐘或仍符合地址的估算，缺少時查 Google；未填時間或仍無法取得車程，不判成可行。此為依排程推算，並非實際客上／客下追蹤，可手動改出發地址，但仍保留目前行程的剩餘時間。

下一趟由時間順序自動帶入尚未完成行程的上車地點與接客時間；也涵蓋跨午夜時的下一日行程。Google Routes 依各段實際預計出發時間估算：出發位置→插單起點、插單起點→插單終點、插單終點→下一趟起點。提早到插單起點要等接客時間；插單上下車各預留 5 分鐘，可調整 0–60 分鐘。Google Places 多候選須選地點，AI 地址必須出自原文。

插單可準時接客且不延誤下一趟，按鈕呈綠色；插單接客晚到、下一趟延誤或既有排程重疊／尚未確定則呈紅色並列原因。未算完、失敗或資料不足維持中性色，不使用零分鐘假值。彈窗列出三段車程、接客與下車完畢時間、下一趟抵達時間及剩餘／延誤分鐘。今天以外的插單須改日期或另行處理，不以今天空檔判綠色。

結果最長有效 5 分鐘；排程修改、目前行程結束、下一趟開始或等待已用完可用餘裕時提前失效。只有仍有效且可行時可按「Send Message back」，確認後回覆原聊天室 `xx分可到<插單起點>`；分鐘包含目前行程尚需等待的時間與前往插單起點的車程，向上取整。

## App 圖示通知圓點修正

背景常駐通知移至不顯示 badge 的新通知頻道，移除舊頻道；此移轉是因 Android 已建立頻道的 badge 設定不能直接改寫。搶單通知保留正常提醒。標為已讀、全部已讀、關鍵字取消命中或切換來源後，會撤除已不符合未讀條件的系統通知；即使訊息已超出最新 500 筆清單也會同步處理。發通知前再次檢查未讀狀態，避免剛標已讀卻又跳出舊通知。

## Page 2 客上／客下回報

Page 2 的「回報對象」設定 LINE 聯絡人或聊天室完整名稱，預設 `小明`，儲存後重啟仍保留。客上／客下按鈕會複製現有字串（含姓名／去回程），並透過 Page 5 的同一條連線送給該對象。斷線時仍複製，回報標為未送出；不會自行排隊重送。

Page 2「回報紀錄」及 Page 5「傳送紀錄」可檢查狀態。只有對應 request_id 的 `send_result: success` 才顯示 Server 確認已送出。60 秒未回執、送出途中斷線或 App 中斷都標為結果不確定，不自動重送。上下車回報可在紀錄中確認後重送；搶單回覆需回原訊息重算。這是 Server 回執，不等同接收人已讀。

SQLite v2 新增 outbox，保留原有訊息和同步游標；來源與操作識別共同阻止重複點擊。同一行程、上下車狀態、對象及文字成功回報後不再次傳送；若需要重報，只有明確失敗或結果不確定的紀錄能手動確認重送。

## 驗證

`LineFlowTest` 涵蓋關鍵字正規化、Token URL 編碼、錯誤來源與欄位拒絕、500 筆分頁與同步／推送交錯、去重、補收時效、空白初始同步、寫入失敗，以及 MockWebServer 真正 WebSocket 握手與失效 Token 停止重試。

`MessageActionsTest` 涵蓋自訂／清空關鍵字、第一地址與 AI 原文驗證、分钟取整與過期、GPS 座標路線請求、送出內容／對象編碼、回執配對與逾時不重送。尚需手機端確認定位授權、彈窗操作和實際 LINE 回報。

`InsertionFeasibilityTest` 涵蓋執行中／已完成行程、未知車程／時間、三段路程、上下車緩衝、等候指定接客時間、插單接客遲到、下一趟延誤、區間接客、重疊行程、排程修改與餘裕耗盡後失效、跨日銜接及 AI 地址驗證。圖示圓點與定位仍需裝置驗收。

裝置驗收：設定有效 Token → 同步完成 → 由 LINE 收到含關鍵字的新訊息 → 驗證頁籤／卡片／系統通知 → 點通知進 Message → 標為已讀 → 背景接收 → 斷網恢復 → 確認只補收一次 → 更新錯誤 Token，確認停止重試。實際通知彈出還需在裝置上確認。


### 收訊時提前評估
新關鍵字訊息（含最近兩分鐘的重連補收）會自動解析並嘗試完整評估；首次歷史同步不批次呼叫 AI。最多同時處理兩則，依連線來源及訊息序號共用進行中的工作，切頁不會遺失結果。記憶體保留最近 200 則分析，程序重新啟動後可開啟評估重新解析。

需要現在位置但 App 不在前景，或地址有多個候選時，先保留解析資料並提示開啟評估補齊；不自行選取同名地址。未取得完整路線不會標成綠色。接客日期預設今天，按日期修改才展開；明確「即時可等」優先套用，否則使用 AI 擷取的接客時間。移除「辨識待確認」文字。

「發送訊息」保持可按，評估不可行、過期或尚未完成皆可開啟編輯與確認視窗。已有結果帶入計算分鐘數；沒有結果可手動填寫。回覆格式為「xx 分 可到 OOO」，OOO 使用 LINE 原文上車地址，地圖標準化不會覆寫原文。分鐘數及原文地址可修正。實際傳送仍需連線及有效聊天室，確認後才送出；自動分析不會自動回覆。
